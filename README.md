# 🚉 Система технического мониторинга и контроля объектов транспортной инфраструктуры (СС ТМК)

### 📝 Описание проекта
Данный проект представляет собой объектовое решение и программный интерфейс (API) для интеграции консоли оператора в единую инженерно-техническую систему обеспечения транспортной безопасности ОТИ. 

Архитектура системы разработана в соответствии с базовыми требованиями Министерства транспорта РФ к интеграционным шлюзам мониторинга безопасности (спецификация 2013 г.). Она обеспечивает сбор, предварительную обработку, структурирование и хранение данных, поступающих от разнородных датчиков нижнего уровня и систем ситуационной видеоаналитики.

---

## 🏗️ Функциональная архитектура и подсистемы

Объектовая компонента Системы мониторинга функционально включает в себя три подсистемы:
1. **Подсистема сбора данных:** Автоматический опрос и прием сигналов от инженерно-технических средств ОТБ (видеонаблюдение, охранная сигнализация, СКУД, датчики периметра).
2. **Подсистема предварительной обработки и формирования событий:** Фильтрация входящих сигналов нижнего уровня и их сопоставление с заложенными математическими моделями угроз.
3. **Подсистема взаимодействия с внешними системами (API):** Расширяемый программный интерфейс для передачи агрегированной информации на верхний уровень ситуационных центров и консолей операторов.

---

## 🪵 Иерархия формируемых событий

Все возникающие в системе сообщения выстраиваются в строгую логическую структуру для исключения ложных срабатываний:
* **Координаты (Сигналы):** Все возможные сырые состояния и триггеры, поступающие с физических датчиков безопасности.
* **Событие нижнего уровня:** Первичное сообщение, генерируемое аппаратными средствами при срабатывании конкретного датчика.
* **Модель состояния безопасности (Стратегия):** Алгоритмическая совокупность информации, характеризующая защищенность объекта от актов незаконного вмешательства (АНВ).
* **Событие верхнего уровня:** Происшествие или инцидент, сформированный в ходе автоматической отработки модели безопасности (например, *«Проникновение в Аэровокзал Шереметьево»* или *«Частичная неработоспособность ЛВС»*).

## 💻 Спецификация интеграционного Web-сервиса (API)

Шлюз интеграции консоли оператора поддерживает стек протоколов **TCP/IP** (технология Ethernet 100BASE-T/1000BASE-T) и использует унифицированный формат обмена данными на основе **XML/WSDL**. Базовый веб-интерфейс консоли и API разворачиваются на порту **`9988`**.

### Основные методы программного интерфейса:

| Метод API | Тип данных (Вход) | Назначение метода |
| :--- | :--- | :--- |
| **`AddEvent`** | `dateTime`, `eventCoords` (Массив ID датчиков) | Регистрация событий от технических средств нижнего уровня. |
| **`AddEventEx`** | `ObjectEventData` (Классификация, причины, ОТИ) | Создание и передача в систему высокоуровневых инцидентов. |
| **`GetKnownCoords`** | *Отсутствуют* | Получение полного перечня доступных координат (датчиков) объекта. |
| **`GetKnownStrategies`**| `getAutoStrategies` (`boolean`) | Запрос списка всех активных моделей и стратегий безопасности. |
