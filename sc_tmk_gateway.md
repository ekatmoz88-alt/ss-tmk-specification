# Программный шлюз датчиков «СС ТМК» на протоколе MCP 🛰️

Данный модуль реализует интерактивный интеграционный шлюз **SS-TMK-Sensor-Gateway** на базе спецификации **Model Context Protocol (MCP)** и протокола **JSON-RPC 2.0**. 

Шлюз обеспечивает сквозную трансляцию событий нижнего уровня от технических средств обеспечения транспортной безопасности (ТСОТБ) в аналитическую панель мониторинга **«СС ТМК»**, а также автоматический импорт метаданных СУБД из схем проектирования Oracle.

---

## 🛠️ Перечень предоставляемых инструментов (MCP Tools)

Интерфейс шлюза декларирует три ключевые функции для интеграции с внешними AI-агентами и аналитическими системами:

### 1. `GetKnownCoords`
* **Назначение:** Получение полного актуального списка зарегистрированных датчиков (координат) на объекте транспортной инфраструктуры (ОТИ).
* **База данных координат по умолчанию:**
  * `т1`: Камера ситуационной видеоаналитики — Периметр Юг
  * `т2`: Датчик СКУД — Вход в терминал А
  * `т3`: Извещатель охранный — Зона транспортной безопасности
  * `т4`: Камера распознавания номеров — КПП-1
  * `т5`: Сенсор целостности ограждения — Сектор 5

### 2. `AddEvent`
* **Назначение:** Регистрация спорадических сигналов тревоги и событий реального времени при срабатывании периметральных или системных датчиков ТСОТБ.
* **Входные параметры:** `sensor_id` (строка, валидируется по внутренней БД).
* **Логика работы:** Генерирует форматированный отчет с фиксацией точной метки времени (`YYYY-MM-DD HH:MM:SS`) и передает его в подсистему предварительной обработки для верификации моделей угроз ОТИ.

### 3. `ParseDesignXML`
* **Назначение:** Автоматический разбор XML-схем дизайна баз данных `Oracle SQL Developer Data Modeler (OSDM)`.
* **Входные параметры:** `xml_content` (строковый XML-текст конфигурации).
* **Логика работы:** Использует встроенный парсер `xml.etree.ElementTree` для безопасного извлечения атрибутов дизайна (Имя схемы, Уникальный ID, Автор `createdBy`) с целью динамической привязки физических датчиков к таблицам реляционной СУБД.

## 🔀 Архитектура обмена данными

Шлюз функционирует в асинхронном режиме, используя потоки стандартного ввода (`sys.stdin`) для чтения запросов и стандартного вывода (`sys.stdout`) с принудительным сбросом буфера (`sys.flush()`) для мгновенного возврата ответов.

### Пример входного запроса на вызов инструмента (`tools/call`):
```json
{
  "jsonrpc": "2.0",
  "id": 42,
  "method": "tools/call",
  "params": {
    "name": "AddEvent",
    "arguments": {
      "sensor_id": "т1"
    }
  }
}
```

### Пример успешного ответа шлюза:
```json
{
  "jsonrpc": "2.0",
  "id": 42,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "[СС ТМК API | AddEvent]\nСтатус: Событие нижнего уровня успешно зарегистрировано\nВремя: 2026-10-23 18:51:00\nИсточник (Координата): т1 (Камера ситуационной видеоаналитики — Периметр Юг)\nРезультат: Сигнал передан в подсистему предварительной обработки..."
      }
    ]
  }
}
```
